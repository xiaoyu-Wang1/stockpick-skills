# 闲聊调研法（Scuttlebutt）— 个人投资者可执行版

费雪的方法核心：**不只看财报，要从公司生态的每个节点旁证交叉验证管理层叙事**。原版依赖大量实地访谈，个人投资者无法完全复制，本文件给出用公开信息能做到的等效版本，并明确标出做不到的部分。

## 一、六个旁证节点（公开信息版）

| 节点 | 可获取的公开信息 | 用来验证什么 |
|---|---|---|
| **客户** | 大客户/上市公司年报中的供应商披露、招标公告与中标记录、电商与社区真实评价、客户续约与流失公告 | 收入是否真由终端需求驱动；订单集中度；口碑与产品力是否匹配财报增速 |
| **供应商** | 上游公司年报的"前五大客户"披露、采购与预付款变化、供应链新闻 | 公司对上游议价力；采购规模与其披露的收入增速是否自洽 |
| **竞争对手** | 同行年报的行业表述与自身份额、价格战与产能公告、专利互诉记录 | 管理层说的"领先地位"是否被对手承认（对手把它列为主要竞争者本身就是旁证） |
| **行业第三方** | 权威行业协会/统计、认证与准入名单、招标平台数据、券商/咨询的量价数据 | TAM 与渗透率；技术路线切换风险 |
| **前员工** | 招聘平台岗位结构与 JD 变化、离职员工社区讨论、脉动（大规模招聘 = 扩张，长期缩招 = 停滞） | 组织健康度、管理深度、真实产能利用与项目进度 |
| **渠道/经销商** | 经销商上市公司年报、渠道库存与批价数据（消费类尤佳）、终端动销 | 是否存在压货式增长（收入涨、渠道库存涨、终端动销平） |

## 二、执行纪律（防止把闲聊法变成确认偏误工具）

1. **先写假设，再找证据**：调研前明确写下"我预期在 X 节点看到 Y"，然后如实记录是否看到。**主动去找与自己结论相反的一条旁证**（费雪本人极重视反证）。
2. **区分"缺失"与"负面"**：拿不到旁证 ≠ 公司有问题。缺失写入 `data_gaps`，降低 `confidence_grade`；只有拿到**明确的负面旁证**才扣分。
3. **单一来源不采信**：任何关键结论至少两个独立节点互证。只有社区传闻 → 标 C，不作为判据。
4. **不做伪装的实地调研**：个人投资者没有条件访谈上下游高管。若报告里出现"据产业链调研了解"而无出处，属于编造——严格禁止。

## 三、对财报的三项交叉检验（闲聊法的量化落地）

```
① 收入 vs 现金：营收增速 与 (销售收现/应收账款增速) 是否自洽
   背离 → 渠道压货或提前确认收入（要点 4/12 负面）
② 收入 vs 采购/产能：上游采购与资本开支是否撑得起披露的产销规模
   背离 → 收入真实性存疑（升级 RF-04 复核）
③ 份额叙事 vs 对手承认：管理层称"第一"，对手年报与第三方份额数据是否一致
   不一致 → 定性打分降级
```

## 四、输出要求

在 `data_pack` 之外的旁证结论，写入契约的 `qualitative[]` 项，每条 `rationale` 必须带出处；无法验证的维度在 `data_gaps` 中写明"闲聊调研仅完成客户/渠道两节点，供应商与竞品节点缺公开数据"，并将整体 `confidence_grade` 定在 B 或 C。
